# AGENTS.md – Инструкции для AI-ассистентов

Этот файл содержит критически важный контекст о проекте, архитектуре и правилах взаимодействия для любых AI-агентов, работающих с этим кодом. **Всегда читай этот файл перед началом работы.**

## 🎯 Обзор проекта
Это демонстрационный проект (**nue2-demo**) для фреймворка **Nue2**. 
**Важно:** Используемый `nue2` является активным форком оригинального `nuejs/nue`, так как оригинальный проект был заброшен автором. Не ссылайся на устаревшую документацию оригинального Nue, если она противоречит текущей реализации в форке.

## 📂 Структура репозитория
Проект разделен на два основных направления разработки:
1. **`spa/`** – Single Page Application.
   - `ui/` – переиспользуемые HTML-компоненты (например, `entry.html`, `table.html`).
   - `server/` – серверная логика (Nueserver).
   - `css/` – глобальные или компонентные стили.
   - `index.html` – точка входа SPA.
   - `site.yaml` – конфигурация сайта и сервера (включая `reload: true`).
2. **`full/`** – многостраничный, контент-ориентированный сайт (Nuekit + Nuemark).
   - `@shared/` – общие компоненты, макеты и данные.
   - `.md` файлы – контент, который рендерится через Nuemark.
   - `site.yaml`, `Makefile`, `package.json`.

## 🛠️ Технологический стек
- **Runtime**: `bun` (предпочтительный) или `node`.
- **Framework**: Nue2 (Nuekit, Nuedom, Nuestate, Nuemark, Nueserver, Nueglow).
- **Синтаксис**: HTML-first компоненты (`.html`), YAML для конфигурации, минимальный JS для реактивности.
- **Стилизация**: CSS-first, без тяжелых CSS-in-JS или препроцессоров, если это не указано явно.

## 📜 Правила для AI (Строго соблюдать)

### 1. DRY (Don't Repeat Yourself) – Не повторяйся
- **ВСЕГДА** проверяй папку `spa/ui/` или `full/@shared/` перед созданием нового компонента. Возможно, нужный уже существует.
- Если ты модифицируешь компонент, убедись, что не сломаешь его использование в других местах.

### 2. Философия Nue2
- Используй нативную реактивность Nue: `@name`, `:if`, `:for`, `@click`, `@mounted`. **Не предлагай** React, Vue, Redux или Zustand, если пользователь явно не попросил об этом.
- Состояние управляется через **Nuestate** (URL-first или глобальное состояние). Используй его для синхронизации данных между компонентами.
- Разделяй структуру (HTML) и поведение (JS). Избегай inline-скриптов, если это не простая логика компонента.

### 3. Работа с файлами
- **ВСЕГДА** читай содержимое файла (`web_extractor` или аналог), прежде чем предлагать его изменить. Не гадай содержимое.
- При внесении изменений предоставляй полный код файла или четкие, изолированные блоки `diff` / кода с указанием имени файла.
- Не удаляй комментарии или конфигурационные ключи в `site.yaml`, если они не являются причиной ошибки.

### 4. Команды разработки
- Запуск dev-сервера: `bun run dev` или `nue dev`
- Сборка: `bun run build` или `nue build`
- Если ты предлагаешь изменить скрипты в `package.json`, убедись, что они совместимы с `bun` и `nuekit`.

### 5. Стиль общения
- Будь краток. Не пиши длинных вступлений вроде "Конечно, я могу помочь с этим!".
- Сразу переходи к делу: название файла, что изменено и почему.
- Если ты не уверен в API конкретного модуля Nue2 (из-за того, что это форк), прямо скажи об этом и попроси пользователя предоставить код этого модуля из папки `nue2/packages`.
